## 0. Before anything else: billing is live

Rented Vast boxes bill by the hour. They are supervised by processes on **this workstation**.

```bash
vastai show instances --raw | python3 -I -c 'import json,sys; [print(i["id"], i.get("label"), i.get("actual_status"), i.get("dph_total")) for i in json.load(sys.stdin)]'
ps -eo pid,etime,args | awk '/^ *[0-9]+ +[0-9:-]+ python3 tools\/fleet\/fleet.py watch/'   # one watcher per live run
F="python3 tools/fleet/fleet.py"
for r in p0-a p1-a p1-b; do $F status --run $r; done   # boxes, box-hours (budget), spend, snapshots, watchdog
$F health --run p0-a          # ok / warn / fail per box; exit 1 if anything is not ok/warn
tail -n 20 workdir/fleet/runs/p0-a/watch.out
```

- **If a live run has no watcher** (after a reboot or sleep), restart it with the exact command in
  §1. Nothing replaces lost boxes, pulls checkpoints, takes snapshots or ends the run on budget
  without it.
- **The watchdog** is a detached `fleet.py down --run p0-a --after …` process, also on this
  workstation. Its PID is in `workdir/fleet/runs/p0-a/fleet.json`. If it's gone, re-arm it at the
  same deadline: `python3 tools/fleet/fleet.py deadline --run p0-a --respawn-watchdog`. Since
  2026-10-11 it waits on the wall clock, so after a sleep it fires as soon as the workstation wakes.
- **Box-side deadline** (armed 2026-10-11 on all 9 boxes; `tools/fleet/README.md`). An hour after
  its run's watchdog deadline, each box acts by itself: actors destroy themselves and the learner
  stops itself, keeping its disk. It only matters if the workstation is off by then. Check it:
  `cat workdir/fleet-box/logs/deadline.log` on a box (`fleet.py ssh`). If a `down` later finds the
  learner stopped and unpulled, it keeps it (`status` shows `KEPT`). Then
  `vastai start instance <id>` and `fleet.py down --run R --kept`.
- **The three `watch` processes still run the code from before the box-side deadline.** The
  auto-mode classifier blocked restarting them, and the user hasn't decided yet. They work as
  before; a kept learner is out of their reach (it leaves the run's boxes). If a watcher is
  restarted for any reason, the command in §1 starts the current code.
- **Never search with `pkill -f` or `pgrep -f`** on a pattern your own command line contains: it
  matches itself. Find PIDs with the awk pattern above, then kill by PID.
- **Spend:** the user approved ≈ $200 for P0, and on 2026-10-11 **≈ $640 in all** for P0 plus
  both P1 runs (past their $500 line, explicitly). Tell them early if the projection passes that.
  Every new rental needs the user's approval. Destroying boxes after copying their results back
  doesn't.

## 5. Failure modes already met, and their fixes

| Symptom | Cause | Fix (commit) |
|---|---|---|
| A learner start replaced a trained checkpoint with the pilot | bash `[ -f s ] \|\| [ -f i ] && cp …` precedence | `learner_init_line`, tested (`d06a10d`). Budget rebased via `fleet.py rebase` |
| Trainer alive, GPU 0%, queue full | DataLoader worker hit Vast's soft limit of 1,024 open files | `box_supervise.sh` raises it; health `trainer stalled` → `watch` restarts the unit (`05cca12`) |
| First rsync broke seconds after the box answered SSH | The image restarts sshd after boot | `wait_running` needs two answers 20 s apart; syncs retry (`afbd138`) |
| `bench_learner.py` hung after generating its drain (P0's check: 45 min, read as a `torch.compile` hang; P1's check, 2026-10-11) | Loader workers forked after the arena ran in the same process deadlock at 0 CPU | Generation runs in a child process (P1 check commit); the trainers never run the arena |
| Zen 3 customs (7B13, 7C13) were skipped | allowlist regex | fixed (`bee896c`) |
| A background job on the workstation was killed | Claude Code reaps its background shells under memory pressure | keep peak RAM ≲ 10 GB; use `setsid -f` for supervisors |
| Learner hosts lost (`instance exited`) | Vast hosts | `watch --replace` handles it (19.6 min for p0-a). A loss right at the budget makes `full` the last pulled checkpoint |
